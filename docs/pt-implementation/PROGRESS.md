## Shared data and command design checkpoint

- Availability: tenant-local versioned weekly windows, dated replacements, breaks/blocks and gym closures; mutations require scoped receipt/audit and expected version. Candidate slots are evaluated server-side and revalidated under trainer/member serialization at commit. Existing confirmed/active sessions are preserved; affected changes require an explicit review/resolution.
- PT policy: authoritative API policy for in-person, 60 elapsed minutes, one credit, 2-hour minimum notice, 14-day rolling horizon, 12-hour request lifetime and 24-hour cancellation window. Existing sessions retain stored type, times, fee/rate snapshots and remain readable.
- Pending expiry: absolute `requestExpiresAt`, explicit EXPIRED state/event and bounded indexed lookup. Foreground conflicting commands treat due requests as expired under shared locks even if scheduled work is late.
- Booking details: role-filtered session projection, sanitized state-event timeline and server-computed affordances. No member payroll/audit/receipt internals.
- Reschedule/correction: owner-only quote/commit commands with expected version, reason, idempotent receipt and immutable state/schedule/correction facts; financial changes use compensating credit/pay records and never rewrite approved payroll.
- Expiry remedy: owner-approved source allocation/unit and narrowly scoped expiry eligibility adjustment; no new value, repeated approval idempotent, membership still required on use date.
- Reminder work: durable tenant-local rows keyed by session, schedule revision, kind and recipient; bounded claims, retry/lease and state/revision recheck with notification insert in a transaction.

## PT-05 design checkpoint — implementation in progress

- Preserve all original settlements/state events and allocation ordinals. Append owner adjustment records with reason, source event, prior/new outcome and supplied actual times. Effective detail reads use the latest adjustment while original facts remain immutable.
- Restore consumed/expired units with conserved signed bucket transfers, never new issued credits or a pack-wide extension. Source-linked remedy records change eligibility for one original pack ordinal only. A tenant SQL unit projection supplies allocation and balance/value reads consistently, including remainder minor units.
- Rescheduling cancels/settles the original and creates a linked replacement through the existing booking validation inside one tenant transaction. Late member requests consume the source and require another unit; gym/trainer requests release without charge. Failed replacement rolls the entire transaction back.
- Reverse operational earnings with immutable source-linked negative records; add the corrected positive fact when applicable. Extend existing trainer-pay corrections to support multiple signed adjustments and use open correction periods; approved source periods remain unchanged. Signed correction-period totals represent accrual adjustments, not payments.
- Quote/commit commands bind owner, source version/event, intent, exact allocations and effects, with a two-minute validity. Commits revalidate under access fences and consistent settlement/actor/session/pack serialization; stable receipts recover response loss.
- PT-06 will add durable reminder jobs; linked replacement IDs and immutable adjustment records provide the invalidation boundary. There are no reminder jobs to invalidate in the current schema.
